# Описание алгоритмов конфигурации «Запись на приём»

Диаграммы процессов (IDEF0, IDEF3, EPC) лежат в этой же папке. Ниже кратко описана логика основных операций.

## 1. Создание и запись документа «Запись на приём» (ПередЗаписью)

1. Проверить, что заполнены Организация, Исполнитель, Покупатель.
2. Проверить, что дата окончания позже даты начала.
3. Проверить, что табличная часть «Перечень услуг» не пуста; в каждой строке заполнена Услуга и Количество > 0.
4. Если цена в строке не указана, взять её из справочника «Услуги».
5. Сумма строки = Количество × Цена.
6. Запросом найти записи того же исполнителя, пересекающиеся по времени (Начало < Окончание другой записи И Окончание > Начало другой записи, исключая саму запись).
7. Если пересечение найдено — вывести сообщение и отказаться от записи (Отказ = Истина).

## 2. Проведение записи на приём (ОбработкаПроведения)

1. Если статус «Предварительная запись» — движения не формируются.
2. Если статус «Услуга оказана» — в регистр накопления «Оказанные услуги» добавляется приход: Период = дата окончания, Покупатель, Запись = ссылка на документ, СуммаЗадолженности = итог по колонке «Сумма» перечня услуг.

## 3. Проведение документа «Оплата услуг» (ОбработкаПроведения)

1. Проверить, что заполнен Покупатель и есть строки в табличной части.
2. Для каждой строки проверить: запись указана; сумма оплаты > 0; запись проведена и имеет статус «Услуга оказана»; покупатель записи совпадает с покупателем оплаты; сумма оплаты не превышает сумму записи.
3. При любой ошибке вывести сообщение и отказаться от проведения.
4. Для каждой строки в регистр добавляется расход: Период = дата оплаты, Покупатель, Запись, СуммаЗадолженности = сумма оплаты.

## 4. АРМ «Администратор» (планировщик)

1. При открытии формы и при смене периода вызывается ЗаполнитьПланировщикНаСервере.
2. Период отображения: от выбранной даты до +7 дней; шкала — часы.
3. Измерение «Сотрудник» заполняется из справочника «Сотрудники организации» (сотрудники — колонки).
4. Запросом выбираются записи за период; каждая запись — элемент планировщика: зелёный — «Предварительная запись», серый — «Услуга оказана»; текст — покупатель.
5. Двойной щелчок по пустой ячейке — открытие новой записи с заполненными исполнителем, организацией, началом и окончанием.
6. Двойной щелчок по существующему элементу — открытие документа; после закрытия планировщик обновляется.
7. Кнопки «Сегодня», «Неделя назад», «Неделя вперёд» сдвигают период и перезаполняют планировщик.

## 5. Отчёт «Оказанные услуги за период» (СКД)

1. Источник — виртуальная таблица Обороты регистра «Оказанные услуги» за выбранный период.
2. Группировка по покупателям, затем по записям.
3. Ресурсы: оказано (приход) и оплачено (расход).
4. Период задаётся пользователем в настройках отчёта.
